What You Actually Get

Use cases this actually unlocks:

  • Home security lab — isolate a vulnerable VM in its own zone, blast-radius contained by construction, torn down when you're done.
  • Cyber range — stand up attacker/defender/decoy zones per exercise, agent-provisioned, disposable.
  • Agile agentic IT zone management — new project, new isolated zone, no ticket to network ops.
  • Granular zone control without the pain and cost of firewalls. ZeroTier's flow rules act as its own firewall layer, no separate firewall change request needed.
  • Out-of-band network analytics. It even has a tee command to capture packet metadata for point-to-point visibility, while session content stays fully encrypted end to end.
  • Unlimited zones — no 25-node SaaS cap, no per-network pricing tier standing between you and the next test.

Doing this by hand is daunting and tedious: click into a dashboard, name a network, click into member management, authorize each node one by one, repeat every time you need a new zone. That friction is exactly why most people provision one network and never touch it again.

Self-host the controller, and none of that clicking is necessary. Every step is one API call: create a network, authorize a node, assign an IP, each a single curl. That's exactly what makes it ideal for agentic orchestration: an agent can create networks and onboard endpoints with none of the friction a human dashboard demands, turning network zones into something you spin up on demand, as many as you need.

This is how I run my own personal lab today: an agent spinning up separate network zones on demand, for testing and learning, without me ever opening a browser to do it.

Today, I'm sharing exactly how.

What follows is the actual step-by-step: not because you need to type any of it yourself, but so you can see exactly what your agent will be doing on your behalf, and verify it for yourself before you trust it.

Zero Exposure, By Design

Most self-hosting guides solve the setup UI's exposure problem with a rushed manual race against Shodan. An agent skips the race entirely: it never needed the UI to begin with. Here's its plan:

  • Stand up the VPS. Add a sudoer account with passwordless, key-based login. Passwordless matters specifically because an agent can't sit at an interactive prompt and type a sudo password; key-based auth is something it can actually use.
  • Clone the repo and point your agent at it. This is what actually drives everything below: the agent reads the procedure from the repo, then runs the whole controller setup itself using the account you just handed it.
  • Confirm access, then lock the door. Verify key-based SSH login actually works before disabling password auth. Skip this check and you lock yourself out of your own box.
  • The agent starts the ZeroTier controller software on the VPS. This is the piece that will manage your private network from now on. Nothing about it is reachable from the public internet yet, or ever.
  • The agent creates your network, then tells you its ID. This is your one manual step: on your own laptop, run zerotier-cli join <the ID the agent gave you> (or just paste the ID into the ZeroTier client's UI widget), then send the agent the node ID that comes back.
  • The agent authorizes your laptop, then finally turns on the web dashboard. The dashboard only ever answers over the ZeroTier network, never the public internet, and by the time it's up, your laptop is already allowed in.

Once you've stood up the VPS and pointed your agent at the repo, everything from here is what the agent runs. You don't need to type any of it; it's here so you can see exactly what it's doing on your behalf.

Step 1: Confirm key access, then harden

Haven't parked your public key on the VPS yet? DigitalOcean's own guide covers it whether you're creating a fresh droplet or adding a key to one that already exists. Do that first.

From a second terminal, before touching sshd config at all, confirm the key-based login actually works:

ssh -o PasswordAuthentication=no -o PreferredAuthentications=publickey user@vps "echo key-auth-ok"

Only once that prints key-auth-ok does it disable password auth:

sudo sed -i 's/^#\?PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart ssh

Step 2: Start the controller software, nothing web-facing yet

The agent starts a single container running the ZeroTier controller engine. No ports published except the ZeroTier protocol itself, nothing a browser could ever reach.

Step 3: Create the network, then you join it

Using the controller's own local auth token, the agent creates your first network and hands you back its ID. That's your one manual step: run zerotier-cli join on your own machine with that ID, then run zerotier-cli info to get your own node ID. No terminal handy? The ZeroTier client's UI widget does the same thing: paste the network ID in to join, then copy your node ID from the same screen.

Copy-paste this to your agent

Your agent won't know your node ID exists until you tell it. Swap in the ID zerotier-cli info just printed, then send this:

I've joined the network. My node ID is [paste your actual node ID here]. Authorize it on the controller.

The agent authorizes it the same way it created the network: one local API call, no dashboard involved.

This is the zero-trust part in practice, not just in name: joining the network gets you nothing on its own. Every single node, including the one YOU are sitting at, is denied by default until explicitly authorized by ID. Being on the network proves nothing; being authorized does.

Step 4: Only now, turn on the web dashboard

The dashboard is ZeroUI, an open-source web UI for managing a self-hosted ZeroTier controller: networks, members, IP assignments, all the things you'd otherwise click through on `my.zerotier.com`. It goes up last, bound to the mesh it just created, not the public internet.

Public internet: connection refused. Zero exposure.

Over ZeroTier: opens cleanly, for the human who eventually wants to look.

The exact commands the agent runs at every step, including everything that broke and got fixed during live testing, live in the repo: github.com/jymcheong/agentic-zerotier-controller. Clone it, point your agent at it, and go.

Let you in on a secret: it doesn't have to be a VPS at all.

Everything above works the same on a local VM, no rented server needed. I ran this exact flow on my own Mac Mini, with a VM, and joined it from my phone on cellular data, no port forwarding, no static IP. ZeroTier's relay fallback means it connects even through the NAT types that block a direct path, it just costs you an extra hop instead of going peer to peer. The one real caveat: it's only as reachable as your home power and connection are, no VPS-grade uptime.
